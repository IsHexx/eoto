# eoto 品牌定位、品牌故事与产品矩阵命名体系

> **Enterprise Operations To One（企业全业务归一）**

---

## 一、品牌基础设定

- **标准写法**：
  - 视觉呈现使用全小写 **`eoto`**，风格极简、现代，兼具国际 SaaS 的亲和力与高级感。
  - 正式合同与法律文档中使用全大写 **`EOTO`**。
- **统一读音**：
  - 品牌固定读作 **“伊奥托”（`ee-oh-toh`）**。该读音顺口且富有节奏感，避免客户面对四个字母时犹豫发音。
- **品牌 Slogan**：
  - **中文（务实版，面向经营者）**：一个大脑，跑通整家公司。
  - **中文（品牌版，面向官网与发布会）**：万象业务，归一智控。
  - **英文**：*Enterprise Operations, To One.*

---

## 二、品牌故事（Brand Story）

**核心释义**：**Enterprise Operations To One**（企业全业务归一）。

### 为什么要做 eoto？

过去二十年，企业数字化走过一段弯路。销售使用 CRM，仓库使用 ERP，财务使用会计软件，沟通留在钉钉、飞书与企业微信。软件越买越多，公司却分裂成一座座数据孤岛。员工每天充当“肉身 API”，在多个系统之间复制粘贴、反复对账并层层沟通。

**`eoto`** 的诞生旨在终结这种割裂。品牌灵感源自自然界极具协作智慧的生物——**章鱼（Octo）**。章鱼依靠一个中枢统筹全局，多条自带独立神经的触手各司其职。

在 `eoto` 的体系里，销售、进销存与经营财务不再是冰冷孤立的表单工具。它们化作连接在 `eoto Core` 上的智能触手。销售签下一笔订单后，`eoto Flow` 自动锁定库存。`eoto Cash` 同步核算单笔订单毛利与回款计划。所有流转都在对话中自然完成，**复杂留给 AI，确定性留给经营者**。

从分散到协同，从繁琐到直觉——**Enterprise Operations To One**，这就是 `eoto`。

> **视觉延伸建议**：设计 Logo 时，设计师可将 `e-o-t-o` 中间的两个 `o` 设计成相互咬合或流动的节点。该图形象征不同业务系统通过 `eoto Core` 无缝连通。

## 三、产品矩阵命名体系

`eoto` 采用 **“主品牌 + 单音节极简功能词”** 的命名结构。客户既能清晰识别每个独立产品，又能一眼看出它们属于同一套协同生态。

| 架构层级 | 产品名称 | 核心定位与角色 | 演进阶段 |
| :--- | :--- | :--- | :--- |
| 交互与连接层 | **`eoto Link`** | 接入钉钉、飞书与企业微信的交互连接层。员工在协同入口平台的聊天窗口中零学习成本调用 `eoto`。 | 基础设施（贯穿全程） |
| 平台主 Agent | **`eoto Core`** | 平台中枢代理。负责理解经营者与员工的自然语言指令，拆解跨部门任务，并调度各子 Agent 协同执行。 | 核心底座（贯穿全程） |
| CRM 子 Agent | **`eoto Sales`** | 销售与客户增长引擎。管理线索、跟进、报价单与合同。系统自动从聊天与语音中录入客户信息、生成报价并提醒回访。 | 第一阶段（破局） |
| ERP 子 Agent | **`eoto Flow`** | 订单与供应链流转引擎。承接 `eoto Sales` 的签单，管理查库存、锁定库存、采购、发货与交付，完成销售到交付闭环。 | 第二阶段（留存） |
| 经营财务子 Agent | **`eoto Cash`** | 经营财务与利润引擎。不触碰核算报税，专注应收应付、自动催款、供应商付款、单笔订单毛利核算与现金流预测。 | 第三阶段（高溢价） |
| 定制与扩展层 | **`eoto Studio`** | 企业专属定制层。实施团队在此配置客户专属 Prompt、业务规则库、审批流与行业插件。团队无需修改底层主干源码即可极速定制。 | 商业化交付利器 |
