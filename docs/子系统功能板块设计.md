# eoto 子系统功能板块设计

本文档定义 CRM 子系统、ERP 子系统与经营财务子系统的功能板块，以及平台层的功能板块。各子系统的对外接口与主数据模型必须以本文档为准。

---

## 一、设计依据

本文档基于以下输入：

- **同类软件调研**：见 [同类软件调研](./research/同类软件调研.md)。
- **第一版功能清单**：见 [客户痛点与第一版产品范围](./客户痛点与第一版产品范围.md)。
- **子系统架构**：见 [项目立项与战略决策纪要](./项目立项与战略决策纪要.md)。

## 二、设计原则

划分功能板块时，遵守以下原则：

1. **按管理对象划分子系统**：CRM 子系统管理人（客户及客户交易），ERP 子系统管理物（商品及其流转），经营财务子系统管理钱（资金对象）。
2. **按业务对象划分板块**：每个功能板块围绕一类业务对象组织功能，例如线索、合同或服务任务。
3. **数据单一写入**：每类业务数据只由一个功能板块写入。
4. **跨子系统只走对外接口**：功能板块需要其他子系统的数据时，必须调用对方的对外接口或订阅对方的领域事件。
5. **金额可以显示，资金对象不能写入**：任何子系统都可以显示金额与资金状态。只有经营财务子系统可以写入资金对象。
6. **标注演进阶段**：每个功能板块标注首次交付的阶段。第一版只交付标注为第一版的功能板块。

## 三、CRM 子系统（`eoto Sales`）

CRM 子系统管理客户及客户交易，负责订单生命周期中的报价、签约与下单环节。

| 功能板块 | 职责 | 持有的数据 | 首次交付 | 对应功能 |
| :--- | :--- | :--- | :--- | :--- |
| 线索 | 从聊天与渠道中采集线索、分配线索、将线索转化为客户 | 线索 | 第一版 | F06、F07 |
| 客户 | 客户档案、联系人、行业字段、销售负责人分配与交接 | 客户、联系人 | 第一版 | F06、F18 |
| 跟进 | 自动录入跟进记录、回访提醒 | 跟进记录 | 第一版 | F07 |
| 报价 | 报价规则、报价单生成、超权限折扣审批 | 报价规则、报价单 | 第一版 | F05、F08 |
| 合同与订单 | 签约、创建周期性订单与一次性订单、合同与订单的变更与作废，发布订单已创建事件 | 合同、销售订单 | 第一版 | F09、F13 |
| 续费 | 到期提醒、续费清单、生成续费订单 | 续费记录 | 第一版 | F10 |
| 销售分析 | 销售业绩统计、续费率与销售漏斗，通过对外接口读取回款状态 | 不持有数据 | 第一版 | F11 |
| 商机 | 识别增值服务商机、管理商机阶段 | 商机 | 第一阶段 | F12 |

合同与订单板块在第一版只支持周期性订单。一次性订单在第一阶段内交付。

CRM 子系统不包含以下功能：

- **市场活动与营销自动化**：第一阶段不做。
- **出库与发货**：归 ERP 子系统。
- **回款计划与收款**：归经营财务子系统。客户页面通过对外接口显示欠费与回款状态。
- **商品主数据**：归 ERP 子系统。

---

## 四、ERP 子系统（`eoto Flow`）

ERP 子系统管理商品及其流转，负责订单生命周期中的履约环节。进销存中的物品流转归 ERP 子系统，包括采购、库存、销售出库与发货。功能板块分为三组：

- **商品组**：所有行业共用。
- **服务履约组**：第一版交付，服务于代理记账企业。
- **实物履约组**：第二阶段交付，服务于商贸批发与分销企业。

| 分组 | 功能板块 | 职责 | 持有的数据 | 首次交付 | 对应功能 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 商品组 | 商品 | 管理实物商品与服务类商品的主数据、规格与成本 | 商品 | 第一版 | F08 依赖 |
| 服务履约组 | 服务计划 | 销售订单创建后，按订单周期生成服务计划 | 服务计划 | 第一版 | F14 |
| 服务履约组 | 服务任务 | 生成月度服务任务、发送票据收集提醒、更新服务进度 | 服务任务 | 第一版 | F14、F15、F16 |
| 服务履约组 | 服务团队 | 服务负责人分配与交接、人员负荷统计 | 服务负责人分配记录 | 第一版 | F18 |
| 服务履约组 | 履约看板 | 征期看板与预警、服务进度统计 | 不持有数据 | 第一版 | F17 |
| 服务履约组 | 外部软件对接 | 从代账 SaaS 同步纳税申报状态 | 同步记录 | 待评估 | F21 |
| 实物履约组 | 库存 | 多仓库、库存查询、库存锁定、并发扣减与盘点 | 库存 | 第二阶段 | 无 |
| 实物履约组 | 采购 | 采购订单、采购建议与入库 | 采购订单 | 第二阶段 | 无 |
| 实物履约组 | 出库与发货 | 根据销售订单出库、发货、签收与退单回滚 | 出库单、发货单 | 第二阶段 | 无 |

服务任务板块在第一阶段内增加两项功能：

- 客户进度答复（F19）。
- 年度事项任务（F20）。

服务履约组与实物履约组只共用商品组，不共享其他数据。

ERP 子系统不包含以下功能：

- **客户档案、合同与销售订单**：归 CRM 子系统。
- **应收应付**：归经营财务子系统。
- **生产排程（MES）**：不在目标范围内。
- **票据内容采集与识别**：属于核算报税领域。ERP 子系统只跟踪票据收集状态。

## 五、经营财务子系统（`eoto Cash`）

经营财务子系统管理资金对象，负责订单生命周期中的回款环节。

| 功能板块 | 职责 | 持有的数据 | 首次交付 | 对应功能 |
| :--- | :--- | :--- | :--- | :--- |
| 应收 | 根据订单的收费周期生成回款计划、统计应收账龄 | 回款计划、应收 | 第一版 | F22、F26 |
| 收款 | 登记收款、推荐匹配的客户与合同、提交人工确认 | 资金流水（收款） | 第一版 | F05、F23 |
| 催款 | 欠费提醒、多级催款策略、欠费服务标记 | 催款记录 | 第一版 | F24、F25 |
| 应付 | 供应商付款登记与提醒 | 资金流水（付款） | 第二阶段 | 无 |
| 经营分析 | 单个客户服务毛利、单笔订单毛利、付款预测与现金流预测 | 不持有数据 | 第三阶段 | F27 |
| 数据导出 | 按标准格式导出数据至外部会计软件 | 不持有数据 | 第三阶段 | F28 |

> [!CAUTION]
> **严禁在经营财务子系统中增加总账、会计凭证、纳税申报、发票开具与资金划转功能。**

## 六、平台层功能板块

### 1. `eoto Core`

| 功能板块 | 职责 | 首次交付 | 对应功能 |
| :--- | :--- | :--- | :--- |
| 经营问答 | 经营者用自然语言查询三个子系统的数据 | 第一版 | F03 |
| 经营概览 | 通过对外接口汇总三个子系统的数据并展示核心看板 | 第一版 | F04 |
| 人工确认中心 | 接收各子系统提交的确认请求，并通过审批流发送给授权角色 | 第一版 | F05 |
| 组织与权限 | 管理员工、部门与用户角色绑定，执行 RBAC 权限控制 | 第一版 | F01 |

### 2. `eoto Link`

| 功能板块 | 职责 | 首次交付 | 对应功能 |
| :--- | :--- | :--- | :--- |
| 组织同步 | 从钉钉、飞书与企业微信同步员工与部门 | 第一版 | F01 |
| 对话入口 | 在协同入口平台中提供员工对话入口 | 第一版 | F01 |
| 通知与审批流 | 发送消息通知，触发协同入口平台的审批流 | 第一版 | F01、F05 |
| 客户沟通接入 | 获取企业微信中已授权的客户沟通消息 | 第一版 | F02 |
| 消息模板 | 管理发送给客户的消息模板，模板启用前提交人工确认 | 第一版 | F02、F15、F24 |

### 3. `eoto Studio`

第一版不向客户开放 `eoto Studio`。前线部署工程师在 `eoto Studio` 中配置代理记账行业模板，包括以下内容：

- 报价规则。
- 服务任务的节点与时间。
- 续费提醒与欠费提醒的节点。
- 默认消息模板。

## 七、跨子系统边界决策

以下决策基于同类软件调研确定：

| 编号 | 决策 | 理由 |
| :--- | :--- | :--- |
| D01 | 回款计划归经营财务子系统。CRM 子系统通过对外接口展示合同的回款状态。 | 国内 CRM 通常包含回款计划。`eoto` 将资金相关数据集中在一个子系统中。 |
| D02 | 商品主数据归 ERP 子系统。报价规则归 CRM 子系统。 | 商品与成本属于履约数据。价格与折扣属于销售策略。 |
| D03 | 销售订单归 CRM 子系统，与合同在同一个板块中管理。ERP 子系统根据销售订单执行出库、发货与服务履约。采购订单归 ERP 子系统。 | 销售订单记录与客户的交易，属于客户层面。出库与发货记录物品流转，属于物品层面。 |
| D04 | 客户负责人分为销售负责人与服务负责人。销售负责人归 CRM 子系统，服务负责人归 ERP 子系统。 | 代理记账企业的销售人员与服务交付人员分别负责同一个客户。 |
| D05 | 服务履约采用服务计划与服务任务两层结构。 | 参照 Odoo 的项目与任务结构。 |
| D06 | `eoto` 只跟踪票据收集状态，不采集与识别票据内容。 | 票据识别与凭证生成属于核算报税领域。 |
| D07 | 子系统按管理对象划分。金额作为属性可以出现在任何子系统中，资金对象只由经营财务子系统写入。 | 每个子系统只管理一类对象，同时允许显示其他对象的数据。 |
| D08 | 进销存的物品流转不另起子系统，归 ERP 子系统。服务履约组与实物履约组在 ERP 子系统内分组。 | 库存锁定与并发扣减需要在同一事务中读写商品、库存与出库记录。 |
| D09 | 主数据实体订单拆分为销售订单与采购订单两个实体。销售订单归 CRM 子系统，采购订单归 ERP 子系统。 | 每个主数据实体只有一个归属方。 |

## 八、待确认事项

以下事项需要在后续设计中确认：

1. **服务履约的拆分条件**：服务履约需要单独售卖或独立发布时，团队评估是否拆分为独立子系统。
2. **外部软件对接的优先级**：代理记账企业通常已经使用代账 SaaS。团队需要评估是否将 F21 提前到第一版。
3. **电子签约**：合同与订单板块是否在第一阶段接入电子签约服务。
4. **信用管理**：经营财务子系统是否在第三阶段增加客户信用管理。
