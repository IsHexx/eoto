# eoto 统一术语表与经批准词汇库

本文档是 `eoto` 项目的唯一术语权威来源（Single Source of Truth）。所有项目文档、架构设计、需求说明与代码注释必须统一使用本表中的标准术语。

新增核心概念时，文档作者或 `eoto-doc-steward` 必须先将术语提交至本表，再在业务文档中使用。

---

## 二、架构与研发术语

| 标准术语 | 英文 / 标识 | 词性 | 唯一批准释义 | 禁止混用的别名 |
| :--- | :--- | :--- | :--- | :--- |
| 主 Agent | Main Agent | 名词 | `eoto Core` 中理解自然语言指令、拆解任务并调度子 Agent 的执行代理。 | 总 Agent、调度 AI |
| 子 Agent | Sub-Agent | 名词 | 隶属于特定业务能力的执行代理，通过标准工具接口操作订单引擎。 | 子智能体、业务机器人、分支 Agent |
| 订单引擎 | Order Engine | 名词 | `eoto Core` 中管理订单生命周期业务状态机的确定性业务内核。所有业务能力通过订单引擎读写订单数据。 | 订单中心、订单系统、交易引擎 |
| 业务能力 | Business Capability | 名词 | 负责订单生命周期某个环节的一组子 Agent 与标准工具接口。包括接单能力、履约能力与回款能力。 | 业务域、业务模块、子系统 |
| 协同入口平台 | Collaboration Host Platform | 名词 | 企业日常使用的外部聊天与办公平台，特指钉钉、飞书与企业微信。 | IM 平台、聊天工具、壳子平台 |
| 钉钉 / 飞书 / 企业微信 | DingTalk / Feishu / WeCom | 专有名词 | 三大目标协同入口平台的标准全称。 | 企微、WXWork |
| 主数据模型 | Master Data Model | 名词 | 全平台共享的核心数据库 Schema，按契约版本统一管理实体字段与状态。 | 共享表、统一库、核心表结构 |
| 契约规范 | API / MCP Contract | 名词 | 各代码包对外暴露的接口协议与工具调用标准，存放在 `spec/` 目录。 | 接口文档、调用协议、工具契约 |
| 业务状态机 | Business State Machine | 名词 | 后端控制核心业务实体状态流转的确定性逻辑引擎。 | 状态流转引擎、后端状态逻辑 |
| 标准工具接口 | Standard Tool Interface | 名词 | 供 `eoto Core` 与子 Agent 调用的标准化后端操作接口（Tools）。 | 工具集、AI 接口、操作 API |
| 人工确认 | Human-in-the-loop (HITL) | 名词 | 运行态对资金变动、库存红线与核心审批强制触发的人工复核机制。 | 人工介入、人工兜底、人工干预 |
| 底层主干源码 | Core Trunk Source Code | 名词 | 面向所有客户保持绝对标准化的核心代码库。 | 核心源码、主干代码、标准代码 |
| 编程 Agent | Coding Agent | 名词 | 在研发阶段并行编写代码包的开发代理。 | 开发 AI、写码 Agent |
| 测试 Agent | Testing Agent | 名词 | 在研发阶段编写并执行自动化集成测试的质量保障代理。 | QA Agent、测验 AI |
| 主仓库 | Main Repository | 名词 | `eoto` 仓库。存放文档、契约规范与全部产品代码。 | 母仓库、总仓库、规范库、umbrella 仓库 |
| 代码包 | Package | 名词 | 主仓库 `packages/` 目录下实现单个产品的代码目录，例如 `packages/sales/`。 | 产品仓库、子仓库、模块仓库 |
| 契约版本 | Contract Version | 名词 | 主仓库 `spec/` 目录下发布的主数据模型与契约规范版本，使用 `YYYY-MM-DD` 格式命名。 | 协议版本、Schema 版本、接口版本 |
| 规范级文档 | Normative Document | 名词 | 记录战略决策、产品定义、架构规范与契约规范的文档，执行全部写作规范。 | 正式文档、定稿文档 |
| 探索级文档 | Exploratory Document | 名词 | 存放在 `docs/research/` 的访谈记录、竞品分析与调研笔记，允许保留客户原话。 | 草稿、调研文档、笔记 |

## 三、核心主数据实体

所有代码包与数据库设计必须使用以下六个标准实体名称：

| 标准实体 | 英文标识符 | 唯一批准释义 | 禁止混用的别名 |
| :--- | :--- | :--- | :--- |
| 员工 | `Employee` | 企业内部成员，同步自协同入口平台的组织架构。 | 人、人员、用户（指内部员工时） |
| 部门 | `Department` | 企业内部组织单元，同步自协同入口平台。 | 组织、团队、小组 |
| 客户 | `Customer` | 购买企业产品或服务的外部商业实体与联系人。 | 甲方、买家、商业伙伴 |
| 商品 | `Product` | 企业销售、采购或库存管理的标准标的物（SKU）。 | 货品、物料、产品（在进销存语境下） |
| 订单 | `Order` | 记录销售成交或采购履约明细的核心单据。 | 单子、合同单、交易单 |
| 资金流水 | `CashFlow` | 记录应收、应付、收款与付款明细的经营资金记录。 | 账目、流水账、财务记录 |

## 四、业务与战略术语

| 标准术语 | 英文 / 标识 | 词性 | 唯一批准释义 | 禁止混用的别名 |
| :--- | :--- | :--- | :--- | :--- |
| 经营财务 | Operational Finance | 名词 | 面向经营决策的业务财务领域，覆盖应收应付、催款提醒、单笔订单毛利与现金流预测。 | 业务财务、业财一体（作模块名词时）、老板财务 |
| 核算报税 | Statutory Accounting and Tax Filing | 名词 | 总账、会计凭证与税务申报领域。`eoto` 明确不自研该领域，仅提供标准导出接口。 | 记账报税、传统财务、做账报税 |
| 订单生命周期 | Order Lifecycle (Order-to-Cash) | 名词 | 一笔订单从报价、签约、履约到回款的完整业务链路。 | 销售到交付闭环、签单交付闭环、业务闭环（特指此链路时） |
| 接单能力 | Order Capture | 名词 | 订单生命周期的报价与签约环节，由 `eoto Sales` 提供。 | 销售模块、CRM 能力 |
| 履约 | Fulfillment | 名词 | 订单签约后兑现合同内容的环节，分为实物履约与服务履约，由 `eoto Flow` 提供。 | 交付流转、发货流程、执行 |
| 实物履约 | Physical Fulfillment | 名词 | 通过查库存、锁定库存、采购、发货与签收兑现订单。 | 发货履约、物流交付 |
| 服务履约 | Service Fulfillment | 名词 | 通过按周期生成服务任务、跟踪进度并交付成果兑现订单。 | 服务交付流程、工单流程 |
| 回款能力 | Collection | 名词 | 订单生命周期的回款环节，包括应收应付、催款提醒与单笔订单毛利，由 `eoto Cash` 提供。 | 财务能力、收款模块 |
| 行业模板 | Industry Template | 名词 | 前线部署工程师在 `eoto Studio` 中为一个行业预置的规则、工作流、Prompt 与字段配置。同行业客户企业直接复用。 | 行业包、行业方案、模板套餐 |
| 审批流 | Approval Workflow | 名词 | 依托协同入口平台现有接口触发的业务审批流程。 | 审批流程、签批流 |
| 单笔订单毛利 | Order Gross Profit | 名词 | 结合合同金额与对应采购、履约成本核算出的单笔订单真实毛利。 | 单单毛利、订单利润 |
| 演进阶段 | Roadmap Stage | 名词 | 项目按订单生命周期覆盖深度划分的三个交付阶段：第一阶段、第二阶段、第三阶段。 | 里程碑阶段、版本阶段 |
| 前线部署工程师 | FDE (Forward Deployed Engineer) | 名词 | 驻场协助企业部署 AI 应用的技术实施人员。在 `eoto` 中负责构建行业模板并支持首批客户企业上线。 | 驻场工程师、现场 AI 实施 |
| 文档规范守护者 | `eoto-doc-steward` | 专有名词 | 负责审查、改写与统一全仓库 Markdown 文档术语和写作规范的专用 Agent。 | 文档 Agent、术语 Agent |

## 六、经批准的核心动词表

编写文档时，优先使用下列标准动词，避免同义词漂移与名词化表达：

| 标准动词（中文） | 标准动词（英文） | 批准含义 | 避免使用的替代词 |
| :--- | :--- | :--- | :--- |
| 调度 | dispatch | `eoto Core` 向子 Agent 分配任务 | 派发、分派、指派、驱使 |
| 接入 | connect | `eoto Link` 对接外部协同入口平台 | 挂载、寄生（技术文档中）、打通（特指连接动作时） |
| 锁定 | lock | 在签约后锁定库存，或锁定已发布契约版本的内容 | 冻结、占住、锁死（正式动作描述） |
| 扣减 | deduct | 在发货或出库时减少可用库存数量 | 减去、消减、扣除 |
| 校验 | verify | 验证数据一致性、并发安全或对账结果 | 核验、检验、进行校验 |
| 核算 | calculate | 计算单笔订单毛利、应收应付或现金流 | 算清、测算、统计 |
| 配置 | configure | 在 `eoto Studio` 中设置规则、工作流或插件 | 搭建、部署（特指规则配置时）、set up |
| 导出 | export | 按标准格式输出数据以对接外部会计软件 | 抽离、倒出、输出（特指文件导出时） |
| 确认 | confirm | 由人在高危动作前执行人工复核与批准 | 拍板、兜底、点确认 |
| 审查 | audit | 由 `eoto-doc-steward` 检查文档是否符合术语与写作规范 | 过目、看看、核查 |
