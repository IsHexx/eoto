# eoto 客户痛点与第一版产品范围

本文档从代理记账企业的痛点出发，推导第一版产品的功能范围。研发团队必须以本文档确定第一版的开发范围与优先级。

---

## 一、文档范围

本文档的适用范围如下：

- **首个行业**：代理记账企业。选择依据见 [项目立项与战略决策纪要](./项目立项与战略决策纪要.md)。
- **协同入口平台**：第一版同时接入钉钉、飞书与企业微信。
- **痛点来源**：本文档中的痛点均为团队假设，需要通过客户访谈验证。
- **用户角色**：用户角色定义见 [用户画像](./用户画像.md)。

## 二、代理记账企业的业务流程

### 1. 订单生命周期

代理记账企业的订单生命周期包含以下四个环节：

1. **报价**：销售人员根据纳税人类型、票据量与行业向客户报价。
2. **签约**：客户签订服务合同，通常按年付费。
3. **服务履约**：服务交付人员每月为客户完成核算报税服务。
4. **回款与续费**：财务人员登记服务费收款。合同到期前，销售人员跟进续费。

### 2. 月度服务任务的节点

服务交付人员每月为每个客户完成以下节点：

1. **票据收集**：提醒客户提交发票、银行回单与工资表。
2. **核算**：在外部会计软件中完成核算。
3. **纳税申报**：在征期内完成纳税申报。
4. **税款扣缴确认**：确认税款已经扣缴成功。
5. **报表交付**：向客户交付当月报表。

> [!IMPORTANT]
> **`eoto` 只跟踪以上节点的状态，不执行核算与纳税申报操作。** 服务交付人员必须继续在外部会计软件与电子税务局中完成核算报税。

## 三、客户痛点

以下痛点按用户角色分组。严重程度分为高与中两级。

### 1. 经营者的痛点

| 编号 | 痛点 | 业务影响 | 严重程度 |
| :--- | :--- | :--- | :--- |
| T01 | 年付合同到期后，销售人员未及时跟进续费。 | 客户流失到低价竞争对手。 | 高 |
| T02 | 欠费客户仍在接受服务，应收金额与账龄不清楚。 | 服务成本无法收回。 | 高 |
| T03 | 征期截止前，经营者无法掌握未申报客户的数量。 | 逾期申报会产生罚款与客户赔偿。 | 高 |
| T04 | 销售人员或服务交付人员离职时带走客户。 | 客户资产流失。 | 高 |
| T05 | 客户总数、合同金额、续费率与欠费金额需要人工汇总。 | 经营者无法及时做出经营决策。 | 中 |
| T06 | 经营者不清楚单个客户的收费是否覆盖服务成本。 | 定价依赖经验，部分客户亏损。 | 中 |

### 2. 销售人员的痛点

| 编号 | 痛点 | 业务影响 | 严重程度 |
| :--- | :--- | :--- | :--- |
| T07 | 线索来自多个渠道，跟进记录分散在聊天中。 | 线索跟进遗漏。 | 高 |
| T08 | 报价取决于纳税人类型、票据量与行业，新员工难以准确报价。 | 报价慢且不一致。 | 中 |
| T09 | 新签与续费业绩依赖人工统计。 | 业绩核对耗时并容易产生争议。 | 中 |
| T10 | 客户在沟通中提到工商变更、社保代办等需求，销售人员未能及时跟进。 | 增值服务收入流失。 | 中 |

### 3. 服务交付人员的痛点

| 编号 | 痛点 | 业务影响 | 严重程度 |
| :--- | :--- | :--- | :--- |
| T11 | 每月逐个提醒数十家客户提交票据，客户经常拖延。 | 重复工作量大，征期压力集中。 | 高 |
| T12 | 每个客户的服务任务状态记录在表格中。 | 状态更新滞后，部门负责人无法实时查看。 | 高 |
| T13 | 客户频繁询问是否已申报与应缴税额。 | 重复答复占用大量工作时间。 | 中 |
| T14 | 客户更换负责人时，历史服务记录与特殊事项丢失。 | 服务质量下降并产生差错。 | 中 |
| T15 | 工商年报、企业所得税汇算清缴等年度事项容易遗漏。 | 客户面临罚款与信用风险。 | 中 |

### 4. 财务人员的痛点

| 编号 | 痛点 | 业务影响 | 严重程度 |
| :--- | :--- | :--- | :--- |
| T16 | 客户通过多种渠道付款，财务人员难以将收款匹配到客户与合同。 | 对账耗时并容易出错。 | 高 |
| T17 | 财务人员无法快速列出逾期客户与逾期金额。 | 催款不及时。 | 中 |

## 四、从痛点到功能

### 1. 优先级定义

功能优先级分为三级：

- **P0**：第一版必须交付。缺少该功能，订单生命周期无法完整运行。
- **P1**：第一阶段内交付，在第一版上线后迭代。
- **P2**：第二阶段或第三阶段交付。

## 五、第一版功能范围

第一版包含 21 个 P0 功能，覆盖订单生命周期的全部四个环节：

| 产品 | 第一版功能 | 功能数量 |
| :--- | :--- | :--- |
| `eoto Link` | F01、F02 | 2 |
| `eoto Core` | F03、F04、F05 | 3 |
| `eoto Sales` | F06、F07、F08、F09、F10、F11 | 6 |
| `eoto Flow` | F14、F15、F16、F17、F18（与 `eoto Sales` 共同交付） | 5 |
| `eoto Cash` | F22、F23、F24、F25、F26 | 5 |

第一版上线后，团队必须能演示以下完整链路：

1. 系统从聊天中识别新客户，销售人员确认后建档。
2. 销售人员生成报价单并签订服务合同。
3. CRM 子系统创建周期性订单。ERP 子系统生成月度服务任务，经营财务子系统生成回款计划。
4. 系统提醒客户提交票据，服务交付人员更新服务进度。
5. 经营者在征期看板中查看未完成户数。
6. 财务人员确认收款登记，系统更新应收账龄。
7. 合同到期前，系统提醒销售人员跟进续费。

## 六、第一版不做的功能

| 功能 | 不做的原因 |
| :--- | :--- |
| 核算、凭证与纳税申报 | 违反核算报税红线。服务交付人员继续使用外部会计软件。 |
| 发票开具与税控 | 属于核算报税领域。 |
| 在线收款与自动付款 | 违反资金划转红线。 |
| 薪资与社保计算 | 属于 HR 领域。 |
| 实物履约与库存 | 代理记账企业不涉及实物商品。 |
| 面向客户企业的独立 App | 客户通过企业微信接收消息，不需要独立 App。 |
| 单个客户服务毛利 | 需要工时数据，安排在第三阶段。 |

## 七、协同入口平台接入范围

第一版对三个协同入口平台的支持范围如下：

| 能力 | 企业微信 | 钉钉 | 飞书 |
| :--- | :--- | :--- | :--- |
| 组织同步 | 支持 | 支持 | 支持 |
| 员工对话入口 | 支持 | 支持 | 支持 |
| 消息通知 | 支持 | 支持 | 支持 |
| 审批流 | 支持 | 支持 | 支持 |
| 获取客户沟通消息 | 支持 | 第一版不支持 | 第一版不支持 |
| 向客户发送消息 | 支持 | 第一版不支持 | 第一版不支持 |

代理记账企业的客户主要使用微信沟通。只有企业微信可以直接连接这些客户。

使用钉钉或飞书的代理记账企业，第一版按以下方式降级：

- **F02**：功能不可用。
- **F06 与 F07**：销售人员将聊天内容转发给 `eoto` 对话入口，系统再识别与录入。
- **F15 与 F24**：系统生成提醒内容，并通知负责人手动发送给客户。

> [!WARNING]
> **必须在客户与员工授权后才能获取客户沟通消息。** `eoto Link` 的接入设计必须写明企业微信会话内容存档的授权流程。

## 八、第一版人工确认范围

> [!CAUTION]
> **必须使用经企业确认的消息模板向客户发送自动消息。** 系统严禁向客户发送未经确认的 AI 生成内容。

第一版的人工确认范围如下：

| 操作 | 默认确认角色 |
| :--- | :--- |
| 收款登记 | 财务人员（限额内）或经营者 |
| 合同作废与退费 | 经营者 |
| 超权限报价折扣 | 部门负责人 |
| 对欠费客户暂停服务 | 经营者 |
| 启用或修改发送给客户的消息模板 | 经营者或部门负责人 |
| 发送客户进度答复（F19） | 负责该客户的服务交付人员 |
