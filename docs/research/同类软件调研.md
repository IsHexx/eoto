# 同类软件调研：CRM、ERP、经营财务与代账行业 SaaS

本文档是探索级文档。本文档调研三个子系统对应领域的现有软件，为子系统功能板块设计提供输入。调研日期为 2026-11-23。

> [!NOTE]
> 本次调研的大部分来源是厂商宣传文章与应用商店介绍，部分功能描述可能偏乐观。团队需要通过产品试用或厂商演示核实关键功能。标注为团队经验的内容未找到公开来源。

---

## 一、CRM 领域

### 1. 调研对象

| 产品 | 定位 | 来源类型 |
| :--- | :--- | :--- |
| 纷享销客 | 国内中大型企业 CRM，主打 AI 与线索到回款全流程 | 厂商合作宣传文章 |
| 销售易 | 国内中大型企业 CRM | 官方操作手册与资料 |
| Zoho CRM | 国际 CRM，在中国提供本地化版本 | 厂商知识库文章 |
| HubSpot Sales Hub | 国际中小企业 CRM | 官方产品页 |

### 2. 主流功能板块

国内 CRM 普遍按线索到回款（LTC，Lead to Cash）流程组织功能。主流板块如下：

1. **市场活动**：记录市场活动，并将活动产生的线索关联到活动。
2. **线索**：多渠道线索汇总、自动分配与质量评分。
3. **客户与联系人**：客户档案、联系人与负责人。
4. **商机**：商机阶段、销售漏斗与赢单预测。
5. **报价**：报价单生成、模板与审批。HubSpot 将报价功能（CPQ）放在独立产品中。
6. **合同与订单**：合同申请、风险审查、电子签约、归档与订单生成。
7. **回款**：纷享销客按合同条款自动生成回款计划，并提供逾期预警。
8. **销售自动化与分析**：邮件序列、销售剧本、业绩看板与预测。

### 3. 关键发现

- **回款通常放在 CRM 中**：国内 CRM 普遍包含回款计划与逾期预警。这与 `eoto` 的经营财务子系统存在职责重叠。
- **AI 集中在录入与预测**：纷享销客宣传从截图、PDF 与 Excel 中解析订单。HubSpot 推出 AI 获客 Agent。
- **企业微信集成的重点是跟进数据**：相关文章建议将联系人、跟进状态与报价需求同步到客户档案，而不是将全部聊天结构化。只同步联系人的 CRM 容易退化为通讯录。

## 二、ERP 与进销存领域

### 1. 调研对象

| 产品 | 定位 | 来源类型 |
| :--- | :--- | :--- |
| 金蝶精斗云 | 国内小微企业进销存与财务 | 官方应用商店页、第三方评测 |
| 畅捷通好生意 | 国内商贸、零售与批发企业进销存 | 第三方对比文章 |
| 畅捷通 T+ | 国内成长型企业业财一体 | 第三方对比文章 |
| Odoo | 国际开源 ERP，按应用模块组合 | 第三方概览文章 |

### 2. 主流功能板块

国内小微企业进销存软件的核心板块如下：

1. **采购**：采购订单、入库与补货建议。
2. **销售**：销售开单、扫码开单与出库。
3. **库存**：多仓库、库存查询与盘点。
4. **财务**：业财一体产品附带应收应付与凭证。

Odoo 的应用分组提供了另一种组织方式：

- **销售组**：CRM、销售、POS、订阅与租赁。
- **库存组**：库存、采购、条码、维护与质检。
- **服务组**：项目、工时、现场服务、服务台、排班与预约。

### 3. 关键发现

- **服务履约与实物履约是两类模块**：Odoo 将项目、工时与现场服务放在服务组，而不是库存组。`eoto` 的服务履约应参照项目与任务的结构设计。
- **订阅单独成为模块**：Odoo 将订阅作为独立应用。这对应 `eoto` 的周期性订单。
- **销售开单属于进销存**：好生意与精斗云都将销售开单放在进销存中。`eoto` 将销售订单放在 CRM 子系统，由 ERP 子系统负责销售出库与发货。

## 三、经营财务与应收管理领域

### 1. 调研对象

| 产品 | 定位 | 来源类型 |
| :--- | :--- | :--- |
| Upflow | 国际应收自动化，侧重催收 | 厂商文章、G2 对比 |
| Tesorio | 国际订单到回款平台，侧重现金流预测 | 厂商文章、G2 对比 |
| Chaser | 国际应收自动化，附带预测功能 | 厂商文章 |

国内尚未找到独立的应收管理软件。国内中小企业的应收功能通常附带在 CRM、进销存或财务软件中。

### 2. 主流功能板块

应收自动化软件的主流板块如下：

1. **信用管理**：客户信用检查与风险分级。
2. **催收自动化**：多级催款提醒与催收策略。
3. **收款匹配**（Cash Application）：将收款自动匹配到发票或订单。
4. **付款预测**：预测客户的付款时间。
5. **现金流预测**：基于应收数据与历史回款率预测现金流。

### 3. 关键发现

- **收款匹配是核心痛点**：评测中多次提到自动匹配发票与收款。这与 `eoto` 的痛点 T16 一致。
- **预测依赖历史回款数据**：Upflow 基于历史回款率而不是付款条款预测现金流。`eoto` 必须先积累回款数据，才能提供现金流预测。

## 四、代理记账行业 SaaS

### 1. 调研对象

| 产品 | 公开信息中的经营管理功能 | 来源类型 |
| :--- | :--- | :--- |
| 柠檬云代账 | 客户档案、收费与欠费提醒、员工权限、客户数据一键交接、客户手机查看服务进度、工商数据获客 | 官方应用商店页 |
| 诺诺云代账 | 商机管理、合同管理、新签与续费管控 | 第三方财经文章 |
| 龙成云代账 | 票据拍照采集与识别入账 | 官方应用商店页 |
| 鲸算盘 | AI 销售、AI 财务、AI 开票与 AI 顾问 | 厂商宣传文章 |

未找到云帐房、慧算账与亿企代账的经营管理功能说明。

### 2. 关键发现

- **代账 SaaS 以核算报税为核心**：主流产品的核心是票据采集、凭证生成与一键报税。经营管理功能作为附加功能提供。
- **经营管理功能已经存在**：柠檬云代账已经提供收费与欠费提醒、客户交接与服务进度查看。`eoto` 与这些功能直接重叠。
- **账套迁移是行业惯例**：柠檬云代账支持从 100 多款财务软件迁移账套。客户更换软件的阻力较低。

### 3. 对 `eoto` 的影响

`eoto` 不能把收费提醒与客户交接作为差异化卖点。`eoto` 的差异化必须来自以下三点：

1. 从企业微信聊天中自动录入客户、跟进与服务进度。
2. CRM、ERP 与经营财务三个子系统之间自动联动。
3. 经营者通过自然语言随时查询经营数据。

> [!WARNING]
> 代理记账企业通常已经使用代账 SaaS。`eoto` 必须与代账 SaaS 共存，不能要求客户替换。团队需要评估是否提前对接主流代账 SaaS（第一版功能 F21）。

## 五、对子系统划分的输入

| 问题 | 市场常见做法 | 对 `eoto` 的建议 |
| :--- | :--- | :--- |
| 回款计划属于哪个子系统 | 国内 CRM 包含回款计划 | 回款计划归经营财务子系统。CRM 子系统通过对外接口展示合同的回款状态。 |
| 商品与价格属于哪个子系统 | CRM 维护价格表，ERP 维护商品与成本 | 商品主数据归 ERP 子系统。报价规则归 CRM 子系统。 |
| 销售开单属于哪个子系统 | 国内进销存包含销售开单 | 销售订单归 CRM 子系统。ERP 子系统负责销售出库与发货。 |
| 服务履约的结构 | Odoo 使用项目与任务结构 | ERP 子系统的服务履约采用服务计划与服务任务结构。 |
| 订阅与周期性收费 | Odoo 将订阅作为独立模块 | CRM 子系统管理周期性订单。经营财务子系统按周期生成回款计划。 |
| 票据采集 | 代账 SaaS 采集票据并生成凭证 | `eoto` 只跟踪票据收集状态，不采集与识别票据内容。 |
